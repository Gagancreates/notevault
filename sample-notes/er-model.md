# Entity–Relationship Model (DBMS Unit 2)

The ER model describes data as entities, attributes and relationships before it is turned into tables. An entity is a real-world object such as Student or Course; an attribute is a property such as roll number or name.

A key attribute uniquely identifies each entity. A weak entity has no key of its own and depends on an identifying owner entity, drawn with a double rectangle.

Cardinality constraints say how many entities take part in a relationship: one-to-one, one-to-many or many-to-many. A many-to-many relationship becomes its own table with foreign keys to both sides when the ER diagram is mapped to a relational schema.
